# Vendored dnsmasq

This directory contains an unmodified copy of the dnsmasq source release,
used to build the `dnsmasq` helper binary that MultiBooter's TFTP boot
feature starts at runtime.

This document records where the code came from, how to verify it and how it
is built.

## 2. How the tarball was imported

The tarball was extracted into this directory, with its top-level
`dnsmasq-2.93/` folder stripped:

```bash
rm -rf src/native/dnsmasq
mkdir -p src/native/dnsmasq
tar -xf dnsmasq-2.93.tar.gz --strip-components=1 -C src/native/dnsmasq
rm -rf src/native/dnsmasq/contrib
```

The result is that the C sources are located at:

```text
src/native/dnsmasq/src/
```

which is the path `build.sh` compiles from.

### Omitted from the upstream tarball

```text
contrib/
```

`contrib/` holds third-party packaging helpers for other platforms
(Slackware, Webmin, old macOS packaging). It is not used by the MultiBooter
build. It also contains opaque archives (`*.gz`, `*.wbm`), so it was left out
to keep the source tree easy to audit.

Nothing else was removed, added or edited. In particular:

- `src/` is byte-identical to the tarball.
- No patches have been applied.

## 3. Local modifications

None.

Any change needed for the Android build is made through compiler flags in
`build.sh`, never by editing the files in this directory.

## 4. Verifying this copy

Download the tarball, check its SHA-256 against the value in section 1, and
compare it with this directory:

```bash
curl -LO https://thekelleys.org.uk/dnsmasq/dnsmasq-2.93.tar.gz
sha256sum dnsmasq-2.93.tar.gz        # must match section 1

mkdir /tmp/dnsmasq-upstream
tar -xf dnsmasq-2.93.tar.gz --strip-components=1 -C /tmp/dnsmasq-upstream

diff -r --exclude=contrib --exclude=UPSTREAM.md \
    /tmp/dnsmasq-upstream src/native/dnsmasq
```

The `diff` must print nothing.

If upstream publishes a detached signature for the tarball, it can also be
verified with `gpg --verify` against the maintainer's published key.

## 5. How it is built

dnsmasq is compiled from source during the MultiBooter build, in step
`[7/15]` of `build.sh`, using the Android NDK clang.

- Input: every `*.c` file directly inside `src/native/dnsmasq/src/`.
- Targets (one binary each): `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`.
- Output: `src/main/assets/dnsmasq-<abi>`. These files are generated by the
  build and are not stored in the repository.
- Flags:

```text
-O2 -fPIE -pie
-DNO_IPV6
-DNO_DBUS
-DVERSION="2.93"
-DETHER_ADDR_LEN=6
-Wno-macro-redefined
-llog
```

`-DVERSION` in `build.sh` must always match the version in section 1.

dnsmasq is a separate program. MultiBooter starts it as an external process;
it is not linked into the application's Java or JNI code.

## 7. Updating

To update dnsmasq:

1. Download the new release tarball from https://thekelleys.org.uk/dnsmasq/
   and record its SHA-256.
2. Delete this directory and import the tarball again as in section 2.
   Do not copy new files over the old ones: `build.sh` compiles every `*.c`
   in `src/`, so a leftover file from an older version would be built too.
3. Update the version and SHA-256 in section 1, and update `-DVERSION` in
   `build.sh`.
4. Build for all four ABIs and verify the result.
5. Update `ASSET_PROVENANCE.md` if the change affects it.
